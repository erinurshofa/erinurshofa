# PORTFOLIO EVIDENCE

## Tujuan

Dokumen ini mengumpulkan **bukti nyata**, bukan sekadar daftar proyek.
Setiap klaim sebaiknya dapat didukung oleh screenshot, data, dokumen,
atau testimoni.

------------------------------------------------------------------------

# Struktur Evidence

Untuk setiap proyek, kumpulkan:

## 1. Identitas

-   Nama Proyek
-   Tahun
-   Klien
-   Jenis Organisasi
-   Status

## 2. Masalah Awal

-   Kondisi sebelum sistem
-   Hambatan
-   Dampak terhadap pengguna

## 3. Solusi

-   Ringkasan solusi
-   Peran saya
-   Teknologi
-   Fitur utama

## 4. Bukti Visual

-   Screenshot desktop
-   Screenshot mobile
-   Dashboard
-   Diagram alur
-   Foto implementasi
-   Foto presentasi
-   Foto pelatihan

Checklist: - \[ \] Homepage - \[ \] Dashboard - \[ \] Form - \[ \]
Laporan - \[ \] Mobile - \[ \] Grafik - \[ \] Foto kegiatan

## 5. Bukti Dampak

-   Sebelum implementasi
-   Sesudah implementasi
-   Efisiensi waktu
-   Pengurangan pekerjaan manual
-   Pengurangan kesalahan
-   Data statistik
-   Grafik

## 6. Bukti Teknis

-   Arsitektur
-   ERD
-   Flowchart
-   Modul
-   API (jika aman)
-   Dokumentasi

## 7. Bukti Pengguna

-   Testimoni
-   Surat tugas
-   BAST
-   Surat implementasi
-   Dokumentasi rapat

## 8. Pelajaran

-   Tantangan
-   Keputusan penting
-   Hal yang akan diperbaiki

# E-SANKEM

## Ringkasan

Klien: Dinas Sosial Kota Semarang

Pengguna: - Kelurahan - Kecamatan - PIC Dinsos - Subkor - Bagian Cetak
SK

## Evidence

### Masalah

-   Berkas berpindah manual.
-   Koordinasi antarinstansi.
-   Durasi layanan dapat mencapai sekitar 3 bulan.

### Solusi

Digitalisasi proses pengajuan dan monitoring.

### Bukti Visual

-   [ ] Homepage
-   [ ] Dashboard
-   [ ] Monitoring Status
-   [ ] Rekap Durasi Layanan
-   [ ] Mobile View

### Bukti Dampak

Data implementasi menunjukkan:

-   Bulan Juni:
    -   Rata-rata durasi layanan: 11,18 hari
    -   Catatan: Masa adaptasi pengguna terhadap sistem.
-   Bulan Juli:
    -   Rata-rata durasi layanan: 3,72 hari

Insight: Penurunan durasi menunjukkan proses menjadi lebih efisien
setelah pengguna mulai terbiasa menggunakan sistem.

### Inisiatif Pribadi

Pada proyek ini saya menambahkan halaman analisis durasi layanan atas
inisiatif sendiri agar dampak implementasi dapat dievaluasi berdasarkan
data, bukan hanya asumsi.

Catatan: Inisiatif seperti ini diterapkan apabila sesuai kebutuhan,
ruang lingkup, waktu, dan memberi nilai tambah bagi klien.

### Pelajaran

-   Discovery lebih penting daripada langsung coding.
-   Pertanyaan yang baik mengurangi revisi.
-   Tidak semua proyek membutuhkan fitur yang sama.
-   Jika memungkinkan, sistem sebaiknya membantu organisasi mengevaluasi
    prosesnya.

# STANDAR EVIDENCE

Sebelum suatu proyek dipublikasikan sebagai portofolio, usahakan
memiliki minimal:

-   5 screenshot utama
-   1 ringkasan masalah
-   1 ringkasan solusi
-   3 pelajaran yang didapat
-   1 bukti implementasi
-   1 bukti dampak (jika tersedia)
-   1 insight yang dapat dibagikan sebagai konten

# PRINSIP

Saya tidak ingin portofolio hanya menunjukkan bahwa saya bisa membuat
aplikasi.

Saya ingin portofolio menunjukkan:

-   masalah yang diselesaikan,
-   cara berpikir,
-   proses pengambilan keputusan,
-   dampak yang dihasilkan,
-   pelajaran yang diperoleh.

Karena bagi saya, nilai sebuah sistem bukan hanya ketika berhasil
dibuat, tetapi ketika benar-benar memberi manfaat.
