# STUDI KASUS 01

# E-SANKEM (SISTEM SANTUNAN KEMATIAN)

## Ringkasan

Klien: Dinas Sosial

Pengguna: - Kelurahan - Kecamatan - PIC Dinsos per wilayah - Subkor
Dinsos - Bagian Cetak SK

Peran: Software Engineer

## Masalah

Sebelum digitalisasi, pengajuan santunan kematian dilakukan secara
manual.

Berkas berpindah antarinstansi.

Petugas harus saling datang.

Status sulit dipantau.

Lama pelayanan dapat mencapai sekitar tiga bulan karena proses saling
menunggu.

## Discovery

Proses dipahami melalui diskusi dengan Subkor Dinas Sosial.

Saya tidak langsung membuat aplikasi.

Saya mencatat proses di notepad dan buku.

Jika ada yang belum jelas saya bertanya kembali, misalnya: - Jika berkas
ditolak? - Jika data salah? - Setelah kecamatan diproses siapa? - Siapa
yang bertanggung jawab?

Setelah alur cukup jelas, saya menggunakan AI sebagai alat bantu untuk
membuat diagram alur dan mempercepat implementasi, kemudian
menyesuaikannya dengan kebutuhan proyek.

## Keputusan Penting

Atas inisiatif sendiri saya menambahkan dashboard durasi layanan.

Tujuannya bukan sekadar menampilkan statistik, tetapi mengetahui apakah
sistem benar-benar mempercepat pelayanan.

Keputusan ini diambil karena pada proyek tersebut kondisi dan ruang
lingkup memungkinkan dilakukan pengukuran.

## Solusi

-   Digitalisasi alur pengajuan.
-   Pemantauan status.
-   Rekap durasi layanan.
-   Monitoring tiap tahapan.

## Dampak

Sebelum: - Proses sekitar 3 bulan. - Sulit mengetahui posisi berkas.

Sesudah: - Berdasarkan dashboard durasi layanan, rata-rata pelayanan
pada awal implementasi sekitar 11,18 hari (masa adaptasi pengguna). -
Setelah pengguna mulai terbiasa, rata-rata turun menjadi sekitar 3,72
hari. - Organisasi dapat mengevaluasi proses berdasarkan data.

## Pelajaran

Proyek ini mengubah cara saya bekerja.

Saya belajar bahwa: - Discovery lebih penting daripada langsung
coding. - Pertanyaan yang tepat mengurangi revisi. - Tidak semua proyek
membutuhkan fitur yang sama. - Jika memungkinkan, dampak sistem
sebaiknya dapat diukur dengan data.

## Insight Konten

1.  Mengapa revisi sering terjadi.
2.  Discovery sebelum coding.
3.  Pentingnya memahami stakeholder.
4.  Cara mengurangi bottleneck.
5.  Mengukur dampak implementasi.
6.  Teknologi mengikuti proses bisnis.
7.  Mengapa dashboard dibuat.
8.  Pelajaran dari proyek pemerintah.
9.  Kesalahan asumsi dalam pengembangan sistem.
10. AI sebagai alat bantu, bukan pengganti analisis.
